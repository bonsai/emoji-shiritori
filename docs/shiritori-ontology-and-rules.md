# しりとり オントロジーとルール

## 1. 目的

「しりとり」を、絵文字カードを操作するゲームとして定義する。

この文書は、ゲームの実装・バランス調整・テスト・レビューで共通に使うための基準となる。

## 2. オントロジー

### 2.1 基本概念

| 概念 | 定義 |
|---|---|
| Card | 1つの絵文字と、その読みを持つカード |
| Emoji | 画面に表示する絵文字 |
| Reading | カードを日本語または英語で読んだ文字列 |
| Head | 読みの先頭文字 |
| Tail | 読みの末尾文字 |
| Field | カードを置く場。現在のターゲットを表す |
| Hand | プレイヤーが保持するカード集合 |
| Deck | まだ配られていないカード集合 |
| Player | 人間プレイヤー |
| CPU | 対戦相手。soloでは存在しない |
| Move | 手札からカードを選び、Fieldへ置く操作 |
| Chain | Tail → Head の一致によって成立するカード列 |
| Stalemate | 誰も合法手を持たず、補充しても進めない状態 |
| Win | プレイヤーが勝利した状態 |
| Lose | プレイヤーが敗北した状態 |
| Draw | 勝敗を決められない同数状態 |

### 2.2 カードモデル

カードは少なくとも次の属性を持つ。

- `emoji`: 表示する絵文字
- `name`: 英語名
- `jaName`: 日本語読み
- `category`: カテゴリ
- `tags`: 補助属性

### 2.3 言語

ゲームは `ja` / `en` の2言語を持つ。

- 日本語モードでは `jaName` を読みとして使用する。
- 英語モードでは `name` を読みとして使用する。

## 3. しりとりの核心ルール

カード A の読みの末尾文字と、カード B の読みの先頭文字が一致すると、A → B の接続が成立する。

```text
Tail(A) == Head(B)
```

したがって、B を A の場に置ける条件は次の通り。

```text
firstChar(reading(B)) == lastChar(reading(A))
```

現在の実装では、この判定を `canPlace(card, target, lang)` が担う。

## 4. 絵文字しりとりとしてのルール

### 通常モード

1. プレイヤーは手札からカードを選ぶ。
2. 場のカードの末尾に接続できるカードだけを置ける。
3. カードを置くと、その場のカードが置いたカードに置き換わる。
4. プレイヤーの手札が空になれば勝利。
5. CPUも同じ接続ルールでカードを出す。
6. 誰も出せない場合、場を補充して再判定する。
7. デッキが尽き、誰も出せない場合は手札枚数で勝敗を判定する。

### Soloモード

Soloは「CPUに勝つ」モードではなく、しりとり操作そのものを練習・継続するモードとする。

1. CPUの手札を持たない。
2. プレイヤーの手札だけを操作する。
3. プレイヤーがカードを出すと、手札を補充する。
4. Soloでは通常対戦のCPUターンを発生させない。
5. UI上は「次に置けるカードを探す」ことを主目的とする。
6. 手札補充は通常デッキが尽きても継続可能な設計とする。

## 5. ゲーム状態

ゲーム状態は概念的に次の集合で表す。

```text
GameState = {
  deck,
  playerHand,
  cpuHand,
  fields
}
```

Soloでは `cpuHand` は空集合として扱う。

## 6. 勝敗

### 通常終了

プレイヤーまたはCPUの手札が0枚になった場合、その側が勝者となる。

### スタレメイト終了

誰も合法手を持たず、デッキから場を補充できない場合。

- プレイヤーの手札枚数 < CPUの手札枚数 → Player Win
- CPUの手札枚数 < プレイヤーの手札枚数 → CPU Win
- 両者同数 → Draw

## 7. 重要な不変条件

実装・テストでは次を守る。

1. 合法手は `Tail(field) == Head(card)` を満たす。
2. 通常モードでは不正なカード配置を受け付けない。
3. SoloではCPUターンを実行しない。
4. カードを出した後、Soloでは手札サイズを可能な範囲で維持する。
5. 通常モードでは、誰も合法手を持たない場合だけ場を補充する。
6. 勝敗判定はカード配置後の最新状態に対して行う。
7. 日本語・英語で同じ抽象ルールを適用し、読みだけを切り替える。

## 8. UI/UX上のルール

- 絵文字は主要なゲームオブジェクトとして視認できること。
- ルールを知らないユーザーでも、次に何をすればよいか理解できること。
- Soloでは対戦情報よりも「置ける／置けない」の理解を優先する。
- ヒント表示はルールを代替するのではなく、ルール理解を補助する。
- 勝敗よりも、しりとりの連鎖を継続する楽しさをSoloの中心価値とする。

## 9. レビュー観点

Soloモードをレビューするときは、特に以下を確認する。

- 手札から合法手を見つけられるか。
- カードを置いた後に次の手が明確か。
- 手札補充が自然に感じられるか。
- 同じカードや状態が不自然に循環しないか。
- デッキ切れでもゲームが破綻しないか。
- 「しりとりをしている」という認知が保たれるか。
- ヒントON/OFFの違いが理解できるか。
- 日本語と英語でルールの意味が変わっていないか。

## 10. 現実のしりとりとの違い

このゲームは日本語の伝統的なしりとりを完全再現するものではない。

カードゲームとして成立させるため、以下をゲーム固有ルールとする。

- 文字ではなく絵文字カードを使う。
- 読みはカードデータに定義する。
- 場は複数存在できる。
- カードを置くと場のカードを置換する。
- Soloでは手札を補充して継続する。
- 通常モードではCPUが自動的に手を進める。

したがって、本ゲームにおける「しりとり」は、**読みのTailとHeadの一致を利用したカード接続ゲーム**として定義する。
